# OPT R54B — committed queue state reconciliation
Base R54A 692a3a05ae72b975d35305c997558f41734d4778. Standalone shadow candidate; no changes to active VM or master.

## Mutation audit
Rechecked queue offer and dispatch, lifetime storage and slot reuse, synchronous R243 thread start, entity entry, death notification/delete, state and animation certificate retirement and actor-script time scope. Relevant source locations at the base: gsc_vm_state.inc:6-7 entity_task_retire marks DEAD; gsc_vm_anim_owner.inc:91 and gsc_vm_animation_refs.inc:14 retire on stale certificates; gsc_vm_delete_transactions.inc releases owned MAIN and retires its task; gsc_vm_entity_entry.inc:54 constructs immediate READY; gsc_vm_r243_thread_start.inc creates immediate children and retires failed children; gsc_vm_r243_actor_script_context.inc:67/88/96 changes and restores the time cursor. gsc_vm_r237_queue_admission.inc writes queue key and owner, while several notification/wait callers publish READY/SLEEP only after the offer. gsc_vm_lifetime.inc clears and reuses physical Task storage. R237 selector considers READY/SLEEP, not the enqueued flag alone. DEAD/EVENT may retain stale fields. Hence a hook on queue_offer alone would be incorrect. This is a targeted audit, not a proof of all writers across the VM.

## Candidate
gsc_r237_queue_sync54.h reconciles all physical rows at one callback-free selection boundary into R54A's caller-owned heap. Begin invalidates visibility, Row accepts sequential committed snapshots and applies only changed index entries, End publishes only a complete snapshot. Invalid, partial, root-change or capacity-change cases cannot expose stale results; when capacity is insufficient caller must fall back or reinitialize with larger backing storage. No Task pointers, VM state writes or allocations. Explicit caller invalidation required before using a result after any mutation/callback. Reconciliation remains O(N) plus O(log Q) per changed heap entry, so is an intermediate shadow verification tool, not a production speedup. Choice returns current task (latest insertion within earliest/current deadline) or earliest future deadline; next is not published when current task exists, matching original drain use. Unique insertion IDs and valid disjoint backing storage remain caller invariants; does not diagnose all duplicate/corrupt states as original scan does. Keep original selector and refusal paths authoritative. Never treat shadow failure as a gameplay error.
