# OPT R55C3B — live array owner directory

Base 6ee0fdfc328acbe8fd0a7ba435135dbb512442a4. Production integration cc51d9448974e5c480256adeddc0022c08238e0d. Master unchanged.

## Implementation
Replace full linear array_entry_find with a read-only owner directory. Head/tail per physical array ID and next per entry are one-based uint16 indices, with zero meaning absent. Every owner chain is ascending physical order, preserving the original first match and exact array_key_equal semantics even for duplicate keys. Out-of-domain owners, mismatched entry counts and detected invalid traversals retain the original reference scan. The directory is derived metadata, not VM-owned script values. Lookups make no writes, allocations or host callbacks. The original source scan was verified text-identical after renaming.

Runtime adds one int plus 4608 uint16 slots (9220 bytes before padding). Zeroed Runtime starts with empty directory. Nine ordinary append sites use array_entry_append55 (ordinary array mutation/getentarray, spawner and spawner team arrays, keybinding, AI arrays, node and vehicle queries, bulletTrace). COW publishes its existing value-only updates and appends exactly as before, then extends from oldEntries. Numeric unlink, four rollback sites, array collector compaction/owner remap, and portable game-array restore rebuild from the committed arena. No change to source callbacks, allocation policy, GC reachability, container counts, key comparison, physical ordering, or COW semantics. Reviewed the 104 direct VM includes and nested runtime includes, plus construction/promotion and known storage snapshots. This is a targeted source audit, not full native execution coverage. Future changes that move entries or change existing keys/owners must preserve the directory invariant. Count agreement alone cannot detect an omitted same-count mutation or every possible corruption. Rebuild costs O(N); a single dense owner can still require O(N) lookup. No FPS claim.
