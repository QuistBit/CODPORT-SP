# OPT R55C2B — bound field lookup to committed high-water range

Base 51fffdce7d22ce0a0407405ffc0bfbfc9acc2388. Integration dd20a3bce2f52139b7e0ac7d5416ee95afae64de. Master unchanged.

## Implementation and invariant
state_field_index previously visits all allocated slots on a miss. Add one private int state_field_scan_end_plus1. Zero means unknown (full original scan); otherwise the decoded upper bound includes every committed used slot. Initial zeroed allocation establishes an empty range, growth preserves it (invalid prior encoding becomes unknown), release clears it. Publish through state_field_publish: write the original whole record to its original slot, then extend the bound, with no callbacks or allocation between them. Holes, out-of-order publication and duplicate identities are legal for the search; do not assume a dense prefix. Unknown metadata stays unknown on publication. Out-of-range metadata falls back to original full scan. This cannot detect an omitted publication hook within an otherwise valid bound, so the writer audit matters.

Reviewed 104 direct VM .inc files from gsc_fixture.c and 38 nested VM includes for direct state_fields/StateField references, plus seven further runtime includes; also inspected runtime construction, promotion and destruction. Identified five record-publication sites: ordinary field write, array root commit, R238 COW root commit, inheritance commit and prepared entity entry. All five now use the same publication helper. Array collection modifies Value contents, not used flags/slot indices; cohort storage copies snapshots for checks, not for restoring field records. Arena growth copies all original records and leaves their indices intact. Constructor promotion reuses original Runtime. This is a source audit, not a full native execution proof. Future field writers must use the helper. No changes to owner identity, case handling, ascending first-match, allocation policy, native/certificate guards or first-free selection. No new cvar, allocations, per-map logic or retained pointers. Only lookup range changes; other full scans remain.
