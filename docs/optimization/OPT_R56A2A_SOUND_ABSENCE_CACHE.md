# OPT R56A2A — exact-byte cache of validated table absence

Base R56A1 0ca75247a13b0efb84ec8b388f2088332bcff220. Runtime integration 219eb660036ca1572704d7e2b6773354084cc684. Pathfinder excluded per user; master unchanged.

## Why this scope
The selected GAME sound adapter currently lists and rereads all CSVs for every resolve; files.c supports FS_Restart and mutable loose resources, but the inspected GAME FS ABI exposes no stable content generation. Map epoch alone is not proof of immutable bytes. Do not retain successful full plans based on alias alone: numeric conversion can depend on the floating-point environment and locale, and selected files can disappear. This stage conservatively caches table-local NONE results only (valid parse with no eligible variants). Such a result has not executed numeric conversion for an eligible row. HELD/errors and READY plans are not cached.

## Implementation
Cod1SS_ParseCached56 uses exact table path, size and memcmp of freshly read bytes, then exact alias/map/profile/loop key. Same-size file changes invalidate all keys for that table. Fresh listing, ordered read/release/current callbacks, ambiguity checking and WAV existence remain unchanged. Other resolver callers use NULL cache. Selected synchronous GAME host owns one cache; clear on GscSoundNotifyReset and map epoch change. Metadata bound 16 tables x 32 keys (ring replacement within a table), 8 MiB total copied CSV bytes plus fixed metadata (141704 bytes measured on local x86-64 ABI, target x86 may differ). Heap allocation only on admission, no change to Hunk; failed allocation or full capacity falls back to original parser. Cache management preserves errno. No foreign references retained, no changes to voice policy, RNG, mixer, notifications or original GSC. No new cvar, default active for selected one-shot host only. Because all VFS reads remain and a matching table still parses in full, this is a limited optimization, not yet elimination of the principal I/O cost. No game timing claim.
