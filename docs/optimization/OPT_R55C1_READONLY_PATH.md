# OPT R55C1 — eliminate unnecessary Value materialization in captured path guard

Base R55B b39adf0c2561a5eb0dfde35f2dc4b47a6cb84d1d. Production change f47ad9b9b1f3e6017aea2123069c8ae64962e6d0.

## Rationale
results_readonly_path in gsc_vm_results.inc runs within the speculative read-only guard for captured array paths. The original copies/zeroes root, current and next Value structures; the comparison helpers use only kind and array ID. The called game_array_selected, game_array_value_valid, state_field_index, array_value_valid and array_entry_find are VM-owned read paths. No callback or allocation in this function. Do not extend pointer lifetimes beyond this boundary or apply the technique to the ordered fallback path, which can run host checks.

## Implementation
Use const Value pointers to existing VM storage and NULL for an absent value (the original zero-initialized V_UNDEFINED). Compare root and captured ancestor exactly as before; start traversal from captured base, retain reverse local lookup and first-match array/field lookup, preserve token checks on game root and handle validation at each step. No persistent cache, no data layout change, no new cvar, no skipped certificates, no map-specific logic. The original ordered guard remains untouched. Source-level materialization of three temporary Values removed, including per-ancestor initialization and copies. A compiler may already eliminate some copies: no measured speedup or FPS claim.
