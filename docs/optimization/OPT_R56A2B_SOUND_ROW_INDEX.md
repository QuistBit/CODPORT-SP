# OPT R56A2B — exact-byte structural index for sound alias rows

Base R56A2A 37c40a272ae5e3251abf826deb3c518fcfbd6ee3. Runtime integration 9a1f3b366b184d4b82001d28b0ef9eeda8570a6b. Pathfinder excluded per user; master unchanged.

## Implementation and invariant
Extend the existing exact-byte cache to retain row offsets after either READY or NONE from a successful complete table parse. Do not retain READY resource plans or HELD errors. Name-first tables only: first non-comment header cell must decode to "name" using the authoritative CSV decoder. For other header orders or resource limits, retain full parser. A valid complete parse has checked the CSV structure of every non-comment row even when its alias did not match; malformed tables cannot establish this invariant. Build the directory in two callback-free passes over the owned copied bytes (count and fill). 256 hash buckets, case-folded FNV-1a, one-based row chains in physical order; original byte offset, line number and full hash per row. The original parser still validates request and parses header, then visits matching hash candidates and verifies actual alias identity. Hash collisions cannot select a different alias. Map filters, original line/error order, numeric conversion, profile, duplicate/sequence checks and ordered variants remain in original parser. No floating-point interpretation cached. No change to list/read/release/current/exists callback sequence, host ownership guards, RNG, mixer, voice or event logic. Same-size file modifications detected via memcmp; existing reset frees both snapshots and directory. No original script change. No new cvar.

## Bounds and tradeoffs
Existing 16 tables, 32 absence keys each and 8 MiB copied bytes retained. New 32768 rows per table and 2 MiB aggregate dynamically allocated row directory limit, 16 bytes/row. Fixed cache metadata sizeof 158352 on local x86-64 ABI (was 141704; target ABI may differ). Total heap payload limit 10 MiB plus fixed metadata and allocator overhead, not Hunk memory. Failed allocation, unsupported header or index capacity exhaustion uses original parser; no repeated index allocation attempt for identical snapshot until reset or content change. Initial successful parse pays additional two passes and allocation; per-request filesystem list/read, exact memcmp and whole-buffer input validation remain. This is a CPU parsing optimization, not an I/O cache. No assertion of actual game speedup.
