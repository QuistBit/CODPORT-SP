Base R56A3A c2c1f12bf00cb548f90932353b3c7a18cac45189 (already published when this turn began). Runtime integration 7a4dd1541f9b1f9af95c2f2342cee00cc514e999. Pathfinder and master untouched.

## Source findings
The GscSoundList adapter invokes trap_FS_GetFileList("soundaliases",".csv",...). SV_GameSystemCalls calls FS_GetFileList -> FS_ListFiles -> FS_ListFilteredFiles. The original non-wildcard pack branch runs FS_ReturnPath for every archive entry, traverses the entire name to count separators, copies the full string to a stack buffer, then checks directory prefix, depth and extension. The copied path is not consumed. Actual archive contents and distribution are not known here; a previous Deck log reported about 60k files in pk3s. This is a plausible repeated cost, not yet isolated in game timing.

## Implementation
FS_PackListMatch56 performs the original bounded case-insensitive prefix comparison and slash test first, then extension checks. Only surviving candidates require complete depth/last-separator computation. The old terminal-separator adjustment, including the single-character corner case, is preserved exactly. No pathname copying in the candidate depth scan. Existing FS_ReturnPath for the query itself remains unchanged. This general optimization applies to the non-wildcard packed enumeration branch, not just soundaliases. Wildcard enumeration, pure-pack admission, live loose-file listing, archive iteration order, deduplication, capacity, basename/directory output and FS_GetFileList packing remain untouched. No persistent index, cache, allocation, new syscall or extra memory. All filenames still visited, O(N) enumeration. No immutable packed-byte lease established; repeated table reads remain live. Avoid caching by archive filename/checksum alone.
