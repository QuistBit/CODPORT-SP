# OPT R54D1 — incremental dirty-slot journal

Base R54C e31927d4a6f9fca62a7a3b4810f5617f9c8f8ec4. Standalone incremental candidate, not wired to VM yet. No changes to active R237 scheduler or master.

## Contract
A caller reports every affected physical slot to R54D_Mark before the next committed scheduling boundary. Mark only records an index and coalesces repeated notifications; it must not read transient Task status. R54D_Begin/Next/Row/End applies only notified slots and newly allocated directory slots, publishes only complete transactions, and forces a complete reseed after invalidation, owner change, shrinking directory or backwards cursor. A dirty slot beyond the committed directory is refused. Dirty or incomplete state is not queryable. No allocations or retained VM pointers; the caller owns valid disjoint heap, reverse positions, dirty list and marker storage. O(1) marking/peek, O(D log Q) reconciliation in ordinary boundaries (D = changed or newly allocated slots, Q = pending tasks), O(N) row feeds on a reseed. R54D_End also checks the minimum deadline against the committed cursor.

Coverage of actual Task mutations is not yet established. Queue offer writes metadata before some callers publish READY/SLEEP; synchronous children can be READY without an enqueued continuation; retirement and reuse may occur elsewhere. A mark omitted by the caller can leave an apparently valid but wrong index. R54D_VerifyRow permits a full reference comparison of every slot, including non-head entries. The caller must invalidate on mismatch. The same assumptions on unique insertion identities per root and valid backing storage as R54A remain; this helper does not replace existing VM integrity checks. No authoritative selection until actual mutation coverage is demonstrated.

## Actual local verification
GCC C11 O2 strict, Clang C11 O2 strict, Clang ASan/UBSan O1 with leak detection: all executed and passed. Each run: 100000 deterministic scheduling boundaries, 979084 incremental row feeds versus 26221633 full-reference rows (including deliberately forced recovery snapshots, excluding initial seed and separate negative cases); 1864 reseeds; 991 deliberately omitted notifications detected by the independent full row audit. Tests cover duplicate marks, cancellation, requeue/rebirth, directory resize, root change, backwards cursor via root reset, incomplete transaction, out-of-range slot, missing stale deadline update and explicit invalidation. After every successful boundary, the full model verifies all rows, queue count, heap invariant, selected slot/serial/insertion and next deadline. 300000 primary boundaries across three repeated compiler runs. The row-count reduction is a model operation count, not timing or FPS; the full audit still reads all rows, so no net runtime saving is claimed. Native game build and actual mutation hooks have not been tested or implemented in this substage. Container git ls-remote failed DNS resolution; no complete Git checkout.
