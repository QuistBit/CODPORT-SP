# OPT R54A — indexed scheduler candidate
Base R53D c63ceecb960ff012dff62ba36e3d40807d72e731. Standalone candidate only. No active VM behavior or master changes.

## Source audit
R237 current scan visits every physical Task slot each selection, considers READY and SLEEP, validates queue owner/insertion/deadline and selects the greatest insertion at the current deadline. Exclusive advances to earliest future deadline, not including target. Current scan re-reads after callback/dispatch. Queue offer validates membership and existing keys, claims a monotonic insertion, writes fields; some callers publish READY/SLEEP only after offer. Synchronous R243 child entry runs immediately, not necessarily through the queued lane. Selected time-root lifecycle and allocation incarnation are distinct from task serial.

Reviewed gsc_fixture.c (thread creation 5287+, notify 5315+/5343+, refresh_wait_owner 5368+, waits/return 5607+/5648+), gsc_vm_results.inc (wait/return 1003+/1149), gsc_vm_event_payloads.inc (offer 113, READY 123), gsc_vm_endon.inc (DEAD 56), gsc_vm_r243_thread_start.inc (synchronous child READY 101, failure DEAD 121), gsc_vm_lifetime.inc (task slot reuse and growth), gsc_vm_r237_queue_admission.inc, gsc_vm_r237_frame_buckets.inc, gsc_vm_r243_time_root.inc. This is a partial mutation audit, not a proof all writers have been enumerated. Need audit context retirement, delete, staged/synchronous scopes, bulk reset and callback-mediated transitions before authoritative index.

## Candidate
Caller-owned binary min heap of (deadline ascending, insertion descending), reverse position index by physical slot. Peek O(1), insert/remove O(log Q), memory O(capacity), no internal allocation, no borrowed Task pointers. Exact root, slot, serial, insertion and deadline required for removal; existing identical key is idempotent. Explicitly assumes disjoint valid caller storage and unique insertion IDs per root; duplicate IDs across slots are not diagnosed like old scan, invalid cursor-relative pending entries are not globally checked. Legacy root stamp zero supported. Do not treat this helper as a replacement for existing VM guards. Need integrate only at committed state transitions, support directory capacity growth and reset, failure rollback/disable, and retain full scan as reference. No active scheduler call site uses this header.
