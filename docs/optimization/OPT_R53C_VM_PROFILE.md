# OPT R53C — scoped VM phase profile
Base R53B 381e18a3486e9925e8c43c6af6d2a4076a214182. Production integration 5b8fd3be7828d82cd1301bdaf59c3eb522960420. No master change.

## Scope
Opt-in GAME cvar g_cod1VmProfile=1; disabled by default, Windows MSVC x86 WIP path only (same platform gate as frame profile). Existing unprofiled Session and VM public phase interfaces remain. The host samples its cvar once per frame, calls the existing unprofiled phase when off, and otherwise passes a synchronous local observer record with QPC clock. No allocation, persistent VM observer, new gameplay option, phase split, queue reorder, or delayed event. Diagnostic adds an output storage separation check and timer calls; not a zero-overhead observer. Callback is the trusted pure QPC function, no VM/host reentry. Counts and durations never control the scheduler. No change to bootstrap behavior (unprofiled).
[OPT_VM53] lane=note/current/exclusive epoch now gen hz result total scan dispatch source endon array scans examined tasks dispatched budget_spent source_calls endon_calls array_calls clock_failures. Raw counter ticks divide by hz; total includes Session checks and VM, scan is directory scan only; source includes interpreter and synchronous native/nested execution and is nested within dispatch. Array is the safe-point collector call, not necessarily a collection; endon similarly measures its boundary call. Budget spent is reduction in VM budget, not hardware instructions. Calls are per phase slice, not whole game ticks; paused slices retain original cleanup semantics. Clock errors are counted, durations from a failed sample omitted. Output one line for phase >=8ms, failures, or periodic sample (at least 1000 game ms since last line per lane). No log per task. Log outside total timer, but parent timers may include logging. A separate measurement with g_cod1VmProfile=0 is still necessary to assess observer overhead. Native host time is not yet isolated from source time.
