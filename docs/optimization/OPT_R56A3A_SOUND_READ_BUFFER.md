# OPT R56A3A — sound CSV read scratch and complete-read admission

Base R56A2B 82c2fe539c1dd4acbd0c4c039d2e8f649fcd56d0. Integration 1bfc6b12659e98eb4ff2a7796aeaa9b098eaddcc.

## Source findings
The selected one-shot and loop-sound paths share GscSoundRead/GscSoundRelease. Every table read allocated a new heap buffer and used the void trap_FS_Read wrapper, discarding FS_Read's return value. The existing trap_FS_ReadCount in g_syscalls.c/g_local.h uses the same G_FS_READ syscall; sv_game.c returns FS_Read. files.c FS_FOpenFileByMode requests uniqueFILE on reads. Packed resource open uses unzReOpen on the archive path; loose paths can override files depending on search order and restriction/pure settings. FS_Shutdown frees search paths and packed handles; FS_PureServerSetLoadedPaks can change the admissible pack set. The current GAME filesystem ABI has no proven immutable resource lease. Do not equate map epoch, archive filename or checksum with proof of unchanged readable bytes. No packed-resource read bypass in this revision.

## Implementation
Shared owner-thread scratch retains up to 1 MiB, expands only as needed. Oversized or nested acquisitions use an independent allocation. Release returns the scratch lease; reset frees it, or defers freeing until outstanding lease release. Reset tied to existing sound/session cleanup and owner map epoch change. Each call still performs original open/read/close, rejects invalid handle and any read count different from requested size, releases buffer on refusal and never publishes partial bytes. Short/failed reads intentionally become resource refusal, not uninitialized data presented to the parser/index. No changes to syscall ABI, parser selection, exact-byte cache, WAV existence, RNG, events, or original GSC. No new cvar, no Hunk allocation. At most 1 MiB additional retained heap, transient oversized/nested allocations as before.
