# OPT R56B1 — integer binary Results dispatch

Base R56A3B c35553c32221885b2117123cf6ac90b9bef9a6dc. Runtime integration cc800a60d181baf87c5f8a7963f6ec3076a348ae.

## Motivation and scope
R55 detailed Deck trace attributed a large share of sampled worst continuation time to animscripts/run::main. Entry identity is not exclusive function timing. Original run.gsc body was not recovered in this pass; this is a general Results VM optimization, not a claim that integer copies are the dominant cost of that script. Inspection of results_eval_checked shows binary operations passing two complete Value objects by value to results_operator, which then dispatches among numerous type families before reaching the selected scalar lane.

## Implementation
results_binary56 takes const pointers to the two already-evaluated operands, with separate caller-owned result. For E_BINARY, selected scalar mode, two V_NUMBER values and exact integer tags (integer==1), bypass the outer generic type dispatcher and call the existing integer_bitwise_binary (if selected bitwise operator) or scalar_binary_selected. Preserve output initialization, scalar profile, int32 payload validation, wrap/overflow semantics, error behavior, and original operator dispatch for all remaining types/modes. No new arithmetic, instruction budget change, cached context proof, allocation or retained pointer. The selected branch cannot invoke a foreign numeric/type adapter; scalar validation errors can call rfail and close precache, but immediately return without further operand use. The unchanged generic by-value operator remains responsible for potentially callback-backed operations; unary and array index paths unchanged. One binary callsite changed. Source-level avoidance of two by-value argument copies in selected lane (compiler may already optimize some copies); no elapsed-time or FPS claim.
