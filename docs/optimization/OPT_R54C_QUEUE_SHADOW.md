## Scope and guardrails
Enable only with +set g_cod1VmProfile 1 +set g_cod1QueueShadow 1 on the existing Windows x86 WIP profile path. Default off. After a successful reference scan, compare the selected task pointer/physical slot, serial, insertion and deadline, or earliest future deadline when no current task exists. All rows are fed to a fresh R54B shadow snapshot, preserving owner checks. The old selector is authoritative: no changes to dispatch, pause return, budget, error messages or cleanup decisions. Reference-rejected scans do not reach the observer. Shadow mismatch or invalid/capacity refusal is diagnostic only. The bounded 1024-slot helper has stack backing (roughly 36-40 KiB depending on ABI), no allocation or retained Task pointer; noinline keeps it off the ordinary path. No persistent state across callbacks. This is a deliberately expensive comparison mode, not the incremental authoritative queue. Timing can influence wall-clock expiration callbacks; do not compare FPS with it enabled.

OPT_QUEUE54 scope=epoch reports cumulative per-lane counters and ticks for valid completed host samples while shadow enabled. Counters reset on map epoch change. A mismatch forces a line; other records follow existing slow/periodic sampling. Invalid clocks or changed epoch/time at phase return are excluded; the last unsampled tail may not appear in the log. Do not sum cumulative rows. checks=matches+mismatches+skipped. A skip is not a match. Existing scan timing excludes the shadow helper; outer timings include its overhead. No new per-task logs.
