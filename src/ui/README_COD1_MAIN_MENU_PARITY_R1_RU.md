# CoD1 UI: главное меню, проход R1

Ветка `ui/native-parity`. Меню по-прежнему читается из оригинальных игровых
PK3: `ui/menus.txt`, `ui/main.menu`, вложенный `ui/menu_background.menu` и
остальные `.menu` нужны при запуске. Исходники проекта содержат обработчики,
а не копии оригинальных ресурсов.

## Подтверждённая структура меню

В переданном пользователем тексте `Вставленный текст(4).txt` есть определение
оригинального `main.menu`: один `menuDef "main"` использует `cl_paused` для
вариантов «в игре» и «из главного меню», открывает отдельные окна для новой
игры, выбора сложности, Resume, Restart, Multiplayer, Options, Quit и
Save/Load. Положение текста, фон, подсветку, оформление и звуки задаёт сам
ресурс. Официальное руководство также показывает Resume, New Game, Load Game,
Multiplayer, Options, Credits, Quit на главной странице меню.

Дизассемблирование предоставленного `uix86(1).dll` (PE timestamp
2004-03-02, SHA256 `dd0738043c287a923357afe53bf2084fda8dd121ece20fcd57828bf5d8c68a4e`)
подтверждает скриптовые команды и их условия:

| Команда | Адрес функции | Подтверждённое действие |
| --- | --- | --- |
| `ingameopen` | `0x4000ebc0` | открывает названное меню при `cl_paused` |
| `ingameclose` | `0x4000ec50` | закрывает названное меню при `cl_paused` |
| `savegamehide` | `0x4000f630` | читает `g_lastSaveGame`, проверяет файл и переключает видимость пункта |
| `restarthide` | `0x4000f6e0` | переключает видимость по состоянию уровня; точный смысл callback оригинального клиента ещё не установлен |

## Что изменено

- `UIMENU_INGAME` открывает тот же `main`, что и оригинальный ресурс; пункты
  выбираются через `cl_paused`. Закрытие `main` из паузы снимает UI keycatcher
  и паузу в существующем `_UI_KeyEvent`.
- `savegamehide` проверяет `g_lastSaveGame` и заголовок реально существующего
  файла. Команда Resume передаёт совместимый путь в `loadgame`. Для порта
  совместимость ограничена текущей `SAVE_VERSION=23`; загрузчик RTCW не умеет
  читать штатные сохранения оригинального CoD1.
- Меню из четырёх сложностей больше не посылает неизвестные движку команды
  `difficultyeasy` и т. п. Оно обновляет `g_spSkill` значениями 1–4 и
  `g_gameskill` значениями 0–3. Движок RTCW принимает значение `GSKILL_MAX=3`
  как самый сложный режим, в том числе включает попадания ИИ в голову.
  Различия урона и ИИ с оригинальным CoD1 пока не сверены.
- `LoadSaveGames` безопасно обрабатывает пустой каталог, короткие имена и
  `.svg` с чужой версией или оборванным заголовком. Их видно как `Unsupported save format`,
  но Load/Delete не передают их несовместимому обработчику RTCW. Проверяются
  версия, минимальная длина, поле описания, NUL в названии карты и диапазон
  даты; при неудаче файловый handle закрывается. Остальное тело сохранения UI
  не разбирает, поэтому повреждение после заголовка может выявиться только
  при загрузке. Удаление перечитывает список.
- Исправлено условие пустого имени у `Savegame2`.

## Проверка и границы

`gcc -fsyntax-only -Wno-implicit-function-declaration -Isrc/ui -Isrc/game
-Isrc/qcommon src/ui/ui_main.c src/ui/ui_shared.c` проходит. `git diff --check`
проходит. Нативный тест `tests/cod1_ui_savegame_test.c` с ASan/UBSan прошёл
280 проверок списка, заголовков и Resume; ещё 20 проверок прошли для действий
`Item_RunScript` → `Script_Exec`. Запуск игры и MSVC сборка здесь не проводились.

На Windows проверить: главное меню до карты; выбор каждой сложности; пауза и
ESC / Back to Game; подтверждение Restart; открытие Save/Load при отсутствии
сохранений, при совместимом `.svg` и при штатном CoD1 `.svg`; Resume после
успешного сохранения. Игровой модуль устанавливает `g_lastSaveGame` после
успешного сохранения; обработчик UI ожидает относительный путь
вроде `save/slot.svg`. В оригинальном `main.menu` действие Load/Save открывает
`save_load_menu`; сам ресурс `ui/save_load.menu` в этой ветке не менялся.

Ни один тест в этой ветке не подтверждает пока визуальный паритет меню Options
и Save/Load с оригинальным CoD1; для этого необходимы кадры из запуска на
Windows и весь набор оригинальных UI-ресурсов.
